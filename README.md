# 拾光咖啡 · 点单小程序

一套代码，同时编译成 **H5 网页** 和 **微信小程序**（Taro 3 + React + TypeScript）。
现在跑的是「本地演示版」：数据存在手机浏览器的本地存储里，不依赖服务器。
等你的小程序账号和微信支付商户号下来，把数据层换成微信云开发、支付层换成微信支付即可，业务代码不用重写。

---

## 现在能做什么

顾客端：

- 看菜单，按分类切换（招牌特调 / 经典咖啡 / 冷萃冰滴 / 茶饮可可 / 甜点烘焙）
- 选杯型、温度、糖度、牛奶、浓度、加料，加价实时算
- 购物车合并同款、改数量、清空
- 选自取 / 堂食，填称呼和备注，下单
- 拿到取餐号（A001、A002…每天从 1 开始），看订单状态（已下单 → 制作中 → 请取餐 → 已完成）
- 「我的订单」查看历史单

店主端（长按首页店名，或滑到菜单最底部点「店主入口」，密码默认 `8888`）：

- **订单**：待接单 / 进行中 / 已完成，一键接单、做好、完成、取消，标记已收款
- **菜单**：搜商品、**新增商品**、**删除商品**、改名称/价格/分类/标签/描述/规格、换商品图、一键「售罄」、一键「上架/下架」
- **分类**：**新增分类**、改名、换图标、删除（有商品时会拦住）
- **店铺**：改店名、一句话介绍、**换首页背景图**、公告、预计出杯时间、电话、地址、到店付款提示、后台密码
- 顶部「营业中 / 打烊中」开关：打烊后顾客端立刻不能下单
- 今日订单数、今日营业额、本地存储占用
- 恢复默认菜单 / 清空所有数据

### 改店名 / 换背景图 / 换商品图

| 想改什么 | 路径 |
|---|---|
| 店名、一句话介绍 | 店主后台 → 店铺 → 品牌外观 |
| 首页背景图 | 店主后台 → 店铺 → 品牌外观 → 首页背景图 → 上传图片 |
| 商品图片 | 店主后台 → 菜单 → 点「改」→ 商品图片 → 上传图片 |

图片是**在手机/电脑上选好就直接用的**，不需要登录任何图床：

- 上传后会自动压到长边 900px（背景图）/ 480px（商品图）、JPEG 质量 0.7 左右，
  一张手机照片通常从 3–5 MB 压到 20–60 KB
- 转成 base64 存在本机，所以不需要服务器
- 随时可「更换图片」或「移除」，移除后回退成 emoji + 渐变色占位
- 本地存储约 5 MB 上限，后台「安全与存储」里能看到当前占用

> 换成云开发后，这两处只要把 `pickImage()` 的结果改成先传到云存储、再存 fileID 即可，UI 完全不用动。

## 跑起来

需要 Node.js 18+。本机已经装好。

```powershell
cd coffee-shop

# 首次：装依赖（约 5 分钟，体积较大）
pnpm install

# 本地预览（H5，浏览器打开 http://127.0.0.1:10086/）
pnpm dev:h5

# 编译微信小程序（产物在 dist/）
pnpm dev:weapp

# 正式构建
pnpm build:h5
pnpm build:weapp
```

> 如果 `node` 不在 PATH 上，先用 `$env:PATH = "<node目录>;$env:PATH"` 补一下。
> 本机可执行文件：`C:\Users\Keefen\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe`

看小程序效果：装「微信开发者工具」→ 导入本目录 → AppID 选「测试号」→ 即可预览（本项目 `project.config.json` 已指向 `dist`）。

## 目录结构

```
coffee-shop/
├─ config/                 Taro 构建配置
├─ src/
│  ├─ app.config.ts        页面注册（新增页面要在这里登记）
│  ├─ app.scss             全局样式变量（配色、圆角、字体）
│  ├─ data/
│  │  ├─ types.ts          数据结构定义（商品/规格/订单/店铺）
│  │  └─ mock.ts           ⭐ 默认菜单数据，改这里就能换菜单
│  ├─ store/index.ts       ⭐ 全局状态 + 所有业务操作（加购物车/下单/改价/售罄…）
│  ├─ components/
│  │  ├─ SpecPopup/        顾客选规格的弹层
│  │  ├─ CartSheet/        购物车弹层
│  │  ├─ ImageField/       图片上传（选图+压缩+预览）
│  │  ├─ ProductEditor/    店主新增/编辑商品
│  │  └─ CategoryEditor/   店主管理分类
│  ├─ pages/
│  │  ├─ menu/             点单首页
│  │  ├─ cart/             确认订单
│  │  ├─ order/            订单详情（取餐号）
│  │  ├─ orders/           我的订单
│  │  └─ admin/            ⭐ 店主后台
│  └─ utils/
│     ├─ format.ts         金额（分）、时间格式化
│     └─ image.ts          ⭐ 选图 / 压缩 / base64，H5 与小程序双端
└─ project.config.json     微信开发者工具项目配置
```

**金额一律用「分」存整数**（`3200` = ¥32.00），避免浮点误差。

## 店主日常怎么改

绝大多数改动**不用找我，也不用改代码**：

| 想改什么 | 在哪改 |
|---|---|
| 上一个新品 | 店主后台 → 菜单 → 右上角「＋ 新品」 |
| 下架不卖了的商品 | 店主后台 → 菜单 → 点「改」→ 左下角「删除」 |
| 价格 | 店主后台 → 菜单 → 点「改」 |
| 商品图片 | 店主后台 → 菜单 → 点「改」→ 商品图片 |
| 把商品换到别的分类 | 店主后台 → 菜单 → 点「改」→ 分类 |
| 卖完了 | 店主后台 → 菜单 → 点「有货」变「已售罄」 |
| 暂时不卖 / 补货 | 店主后台 → 菜单 → 点「已上架 / 已下架」 |
| 加一个分类（比如「气泡水」） | 店主后台 → 菜单 → 右上角「分类」→「＋ 新增分类」 |
| 分类改名 / 换图标 / 删掉 | 同上，在分类面板里直接改 |
| 店名、一句话介绍、背景图 | 店主后台 → 店铺 → 品牌外观 |
| 今日公告、出杯时间 | 店主后台 → 店铺 → 营业信息 |
| 提前打烊 / 第二天开门 | 店主后台右上角开关 |
| 接单、叫号、收款 | 店主后台 → 订单 |

改完立刻生效，顾客端刷新就能看到。

> 新增商品时可以勾选「可选规格」，从现有的杯型 / 温度 / 糖度 / 牛奶 / 浓度 / 加料 / 冰量里挑。
> 如果要一套全新的规格（比如「甜度 0/3/5/7 分」），目前还得在 `src/data/mock.ts` 里加，或者让我补一个规格编辑器。

需要改**代码**的只有：加新页面、改配色、换支付方式。

## 数据存在哪（重要）

目前所有数据（菜单改动、订单、店铺设置）都保存在**当前设备的浏览器本地存储**里，key 是 `coffee-shop-state-v1`。

意味着：

- ✅ 单机演示、自己手机上试，完全够用
- ❌ 顾客手机上的订单，你这边看不到（各存各的）
- ❌ 换设备、清缓存，数据就没了

这正是下一阶段要解决的事 —— 换成微信云开发之后，数据库在云端，就能在任意设备看到所有订单。

## 还没做的

1. **微信云开发**：把 `src/store/index.ts` 里的本地读写换成云数据库读写（需要小程序 AppID + 云开发环境 ID）
2. **微信支付**：小程序内直接扣款（需要营业执照 → 微信支付商户号 → 与小程序 AppID 绑定）
3. **多设备同步**：依赖云开发
4. **图片上云**：现在是压缩后存本地（约 5 MB 上限）。云开发之后改成传云存储、库里只存 fileID，就能放原始大图
5. **规格编辑器**：新增商品只能勾选现有规格组，还不能在后台新建规格组和选项
6. **商品排序**：新商品固定排在分类最后，还不能拖动调整顺序
